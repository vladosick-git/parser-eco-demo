# Эко-сборщик

Демо-проект для портфолио: сбор открытых данных для экологической платформы. Новости об отходах, переработке и экологическом законодательстве, плюс объявления и госзакупки по вывозу и утилизации отходов.

Что показывает проект:

- аудит источников до начала сбора (`docs/AUDIT.md`): robots.txt, условия использования, решение и причина;
- вежливый сбор: свой User-Agent, robots.txt с `*` и `$`, Crawl-delay, пауза от 2 секунд на домен, один запрос за раз, ETag и If-Modified-Since, один повтор при сетевом сбое;
- адаптеры источников с общим интерфейсом: новый источник это один файл, ядро не меняется;
- очистка и нормализация: HTML, даты в ISO 8601, регионы по справочнику, категории, цены, объёмы, ФККО, классы опасности;
- дедупликация по ссылке и по содержанию (одна новость из двух источников не задваивается);
- журнал запусков, изоляция ошибок, уведомление о сбое в Telegram;
- JSON и CSV, статическая витрина с фильтрами;
- тесты без доступа к сети.

Это демонстрация подхода, а не рабочий продукт.

## Что собирается и чего нет

Сохраняются только заголовок, описание до 300 символов, дата, категория, регион, цена и ссылка на первоисточник. Полные тексты статей, контакты, логины, ФИО и телефоны не сохраняются. Организация пишется только если это юрлицо или госорган.

| Раздел | Источники |
|---|---|
| Новости | Минприроды России, РЭО, Отходы.Ру, Экосфера (теги «мусор», «пластик», «законодательство»), журнал «Твёрдые бытовые отходы» |
| Объявления и закупки | ЕИС «Госзакупки» (закупки на вывоз и утилизацию отходов), биржа отходов Отходы.Ру |

Почему именно они и почему отказались от остальных, написано в [AUDIT.md](AUDIT.md). Формат данных в [SCHEMA.md](SCHEMA.md).

## Структура

```
collector/            ядро
  sources/            адаптеры, по одному файлу на источник
  http.py             вежливый HTTP-клиент и разбор robots.txt
  normalize.py        очистка и нормализация полей
  regions.py          справочник субъектов РФ
  dedup.py            ключи и слияние без дубликатов
  items.py            сборка записей по схеме
  runner.py           запуск, журнал, выгрузка
  notify.py           уведомление в Telegram
  certs/              публичный корневой сертификат Минцифры
data/                 результаты: news.json, waste.json, runs.json, CSV
docs/                 AUDIT.md, SCHEMA.md, этот README
fixtures/             сохранённые ответы источников для тестов
site/                 витрина (HTML, CSS, JS без сборки)
tests/                тесты
.github/workflows/    расписание в GitHub Actions
```

## Запуск локально

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
```

```bash
.venv/bin/pip install -r requirements-dev.txt
```

На Windows путь к интерпретатору `.venv\Scripts\python`. Дальше одна команда собирает данные из всех источников и пишет JSON, CSV и журнал:

```bash
.venv/bin/python -m collector
```

Первый запуск длится около 5 минут: госзакупки просят паузу 60 секунд между запросами (Crawl-delay), а у биржи открывается каждое новое объявление. Повторные запуски быстрее, известные объявления повторно не запрашиваются.

Полезные варианты:

```bash
.venv/bin/python -m collector run --only mnr,reo
```

```bash
.venv/bin/python -m collector export
```

`export` пересобирает CSV, `data/sources.json` и `data/bundle.js` без обращения к сети.

### Тесты

```bash
.venv/bin/python -m pytest
```

Сеть в тестах заблокирована (`tests/conftest.py`), адаптеры проверяются на образцах из `fixtures/`.

### Витрина

Проще всего открыть `site/index.html` двойным кликом: данные подтянутся из `data/bundle.js`. Через локальный сервер витрина читает JSON напрямую:

```bash
python -m http.server 8000
```

и открыть `http://localhost:8000/site/`.

## Как добавить источник

1. Проверить robots.txt и условия сайта, добавить строку в `docs/AUDIT.md`.
2. Создать файл в `collector/sources/`, например `my_source.py`:

```python
from .base import RssSource


class MySource(RssSource):
    id = "my_source"
    name = "Мой источник"
    homepage = "https://example.ru/"
    urls = ["https://example.ru/rss.xml"]
```

Для RSS этого достаточно. Для HTML нужно переопределить `parse(content, url)` и вернуть список словарей с полями `title`, `url`, `summary`, `published` (см. `solidwaste.py`). Для объявлений поставить `kind = "waste"` и при необходимости вернуть `price`, `region_text`, `organization`, `offer_hint` (см. `zakupki.py`). Если нужно несколько шагов, например список и карточки, переопределяется `collect()` (см. `wasteru_board.py`).

3. Сохранить ответ источника в `fixtures/` и написать тест разбора в `tests/test_sources.py`.

Ядро найдёт новый модуль само. Отключить источник можно строкой `enabled = False`.

## Расписание и публикация на GitHub

Workflow `.github/workflows/collect.yml`:

- запускается каждый день в 06:15 по Москве и вручную кнопкой Run workflow (`workflow_dispatch`);
- ставит зависимости, гоняет тесты, собирает данные;
- коммитит `data/` от имени `github-actions[bot]`, даже если какой-то источник упал (чтобы ошибка была видна в журнале);
- публикует витрину и данные на GitHub Pages.

Настройка:

1. Залить репозиторий на GitHub.
2. Settings -> Pages -> Source: **GitHub Actions**.
3. Settings -> Actions -> General -> Workflow permissions: **Read and write permissions**.
4. По желанию Settings -> Secrets and variables -> Actions -> добавить `TELEGRAM_TOKEN` (токен бота от @BotFather) и `TELEGRAM_CHAT_ID` (id чата, куда бот может писать). Без них уведомление просто пропускается.
5. Actions -> collect -> Run workflow для первого запуска.

Время запуска меняется в строке `cron` (время в UTC).

Секреты хранятся только в GitHub Secrets. В репозитории есть `.env.example` с пустыми значениями. Для локальной проверки уведомлений переменные можно задать в окружении:

```bash
TELEGRAM_TOKEN=... TELEGRAM_CHAT_ID=... .venv/bin/python -m collector
```

## Ограничения, о которых стоит знать

- **Сертификаты госсайтов.** У mnr.gov.ru и zakupki.gov.ru сертификат от российского удостоверяющего центра. Публичный корневой сертификат Минцифры лежит в `collector/certs/` и добавляется к стандартному набору `certifi`. Проверка TLS не отключается.
- **Доступ из-за рубежа.** Раннеры GitHub находятся за пределами РФ, и госсайты могут им не ответить. В этом случае источник упадёт с ошибкой в журнале, остальные отработают. Вариант для продакшена: self-hosted runner в РФ или запуск по cron на своём сервере.
- **Минприроды** иногда не отвечает на TLS-рукопожатие, поэтому в клиенте есть один повтор через 15 секунд.
- **РЭО** отдаёт всю ленту (21 МБ) без поддержки условных запросов. Записи старше 180 дней отбрасываются.
- **ФККО** ни один из разрешённых источников не публикует отдельным полем. Нормализация реализована и покрыта тестами, но в реальных данных поле почти всегда пустое.
- **Категории и тип предложения** определяются по ключевым словам, это эвристика, а не классификатор.
